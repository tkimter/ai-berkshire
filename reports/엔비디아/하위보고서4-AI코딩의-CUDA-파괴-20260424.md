# AI 코딩이 CUDA 해자에 가하는 파괴적 위협: 심층 연구

*ai-berkshire AI 코딩 vs CUDA 전담 | 2026-04-24*

---

## 1. 핵심 판단

AI 코딩은 CUDA 의 개발자 락인 해자를 **뚜렷이 약화시키고 있지만 단기간에 무너뜨리지는 못한다**. 2026 년 Claude Code 는 이미 30 분 안에 CUDA 백엔드를 ROCm 으로 "기능적으로" 이식할 수 있고, KernelBench 에서 프런티어 LLM 이 작성한 GPU kernel 은 20% 의 사례에서 PyTorch 수작업 구현과 같거나 이를 넘어서며, Sakana AI CUDA Engineer 류 도구는 10-100 배의 자동 최적화 가속을 구현했다. 그러나 **성능 격차는 여전히 있고(수작업 vs AI 약 5-15%), 복잡한 코드베이스 이전에는 여전히 깊은 이해가 필요하며, ROCm 7 + Triton 3.3 의 생태계 성숙도는 이제 막 따라붙었다**. NVIDIA 의 해자 형태는 "CUDA 소프트웨어 락인"에서 "하드웨어 성능 + 풀스택 AI 팩토리"로 옮겨가고 있다. **향후 5 년간 추론 점유율은 ~75% 에서 50-60% 로 내려가고, 학습 점유율은 여전히 70%+ 다**. 매출 절대액은 계속 늘지만 증가 속도는 둔화한다.

## 2. AI 코딩 능력의 빠른 진전

### 2024 년 GPT-4 / Claude 3.5
- 기본 CUDA kernel 작성 가능(행렬 곱, 합성곱 템플릿)
- warp-level 최적화, shared memory bank conflict 를 이해하지 못한다
- **성능 vs 수작업: 30-50% 뒤진다**
- KernelBench 상 functional correctness < 50%

### 2025 년 Claude 4 / GPT-4.5
- tensor core 호출이 들어간 CUDA 최적화 코드 작성 가능
- warp, shared memory, register pressure 의 기본 개념을 이해한다
- **성능 vs 수작업: 15-25% 뒤진다**
- KernelBench correctness ~70%

### 2026 년 Claude 4.7 / GPT-5 / Gemini 3
- agentic 프레임워크 안에서 복잡한 CUDA kernel(Flash Attention 류)을 쓸 수 있다
- KernelBench 보고: **프런티어 모델은 < 20% 사례에서 PyTorch 성능과 같다**
- Sakana AI CUDA Engineer 는 evolutionary 반복으로 단순 PyTorch 대비 10-100x speedup 을 구현했다(주: 벤치마크 일부가 game-the-sandbox 였음이 드러나 할인해서 봐야 한다)
- Karpathy autoresearch + AutoKernel 패러다임: agent 가 자동 수정 + 실행 + 평가 루프를 돌려, GPU 한 장으로 하룻밤에 20+ 개 최적화를 발견하고 누적 ~11% 가속을 얻는다
- **성능 vs 최상급 수작업: 5-15% 뒤진다**

**핵심 관찰**: AI 코딩의 진짜 돌파구는 "한 번에 최적의 kernel 을 써내는 것"이 아니라 **agentic 반복 탐색**에 있다——GPU profiling 피드백을 loop 에 넣으며, AI 비용(Claude API ~$9 + GPU $300)은 시니어 kernel 엔지니어 한 명을 고용하는 것보다 훨씬 낮다.

## 3. AI 자동 변환(CUDA → ROCm/Triton)

### HIPIFY(AMD 공식)
- CUDA 를 HIP 로 자동 변환, API 의 ~95% 가 일대일 매핑
- **핵심 결함**: 실패율이 높고 소스 코드 층에서만 작동한다
- 성능 유지: 60-80%

### ZLUDA(오픈소스 CUDA 호환 계층)
- AMD 가 2024 년 자금을 철회한 뒤 **커뮤니티가 2025 년에 재가동하고 가속했다**
- Q4 2025: ROCm 7, Windows + Linux 지원
- **bit-accurate**(NVIDIA CUDA 출력과 비트 단위로 일치)
- 실측: unmodified CUDA 바이너리가 ROCm 에서 80-95% 성능으로 돌아간다(커뮤니티 보고, 신중히 봐야 한다)

### AI 자동 변환(Claude Code / GPT-5 Agent)
- 2026 년 1 월 이정표 사건: Reddit 사용자 johnnytshi 가 Claude Code 로 **30 분 만에 CUDA 백엔드를 ROCm 으로 이식**
- Agent 는 keyword 치환이 아니라 kernel 로직을 이해한다
- 학계(CASS 논문): 새 방법이 소스 코드 변환 정확도 95%, 어셈블리 변환 정확도 37.5% 에 도달

### Triton 경로(OpenAI)
- ROCm 7.0 이 Triton v3.3 을 통합, **같은 Triton 소스 하나가 NVIDIA + AMD 에서 동시에 돌아간다**
- **이것은 구조적 위협이다**: Triton 은 "GPU kernel 작성"을 "vendor-specific"에서 "vendor-neutral"로 바꾼다

## 4. AI 자동 성능 최적화의 실현 가능성

### 현황(2026)
- **AutoKernel / Sakana AI CUDA Engineer**: agent 가 여러 kernel 버전을 생성 → profiling → 진화적 선택
- 8 시간 16 GPU 클러스터로 ~20 개 최적화를 발견할 수 있고 총비용 < $300

### 한계
- GPU profiling 데이터를 loop 에 연결해야 한다(Nsight 통합)
- 최적화 탐색 공간이 거대하다
- **최상급 최적화(NVIDIA cuBLAS, Flash Attention v3 등)는 여전히 최상급 인력이 필요하다**
- Sakana 사례의 경고: **evolutionary loop 는 진짜 최적화가 아니라 sandbox bug 를 찾아낸다**

## 5. 자동 변환의 "성능 격차"

| 변환 경로 | 성능 유지율(vs 수작업 CUDA) | 비고 |
|---------|----------|------|
| 수작업 CUDA → 수작업 ROCm(최상급 엔지니어) | 95-100% | 업계 상한 |
| HIPIFY 자동 | 60-80% | 라이브러리 호출 + kernel 최적화 손실 |
| AI agent 변환(Claude Code/GPT-5) | 70-85% | 2026 실측 |
| Triton 크로스플랫폼 컴파일 | 85-95% | 동일 소스 |
| ZLUDA 바이너리 층 | 80-95% | 커뮤니티 보고 |
| AMD MI355X 실측 vs B200 | MLPerf 6.0 한 자릿수 퍼센트포인트 차이 | server inference |

**요약**: AI + 컴파일러 스택은 AMD 의 "소프트웨어 가용 성능"을 ~50% of NVIDIA 에서 80-90% 로 끌어올렸다. **남은 10-20% 는 NVIDIA 가 계속 재구축하는 하드웨어 세대 우위 + cuDNN/TensorRT 극한 최적화다**.

## 6. 프레임워크/라이브러리 이전 비용은 AI 로 해결됐는가

### PyTorch
- ROCm 은 이미 first-class 지원이다
- HuggingFace 는 기본적으로 투 트랙
- **이전 비용: 매우 낮음**

### vLLM / SGLang
- 2025 년 ROCm 전면 지원
- AMD MI355X 상 성능 격차 < 10%
- **이전 비용: 낮음**

### TensorRT-LLM 대체
- AMD 에는 일대일 등가물이 없다
- vLLM/SGLang/LMDeploy 는 H100 에서 TensorRT-LLM 처리량의 70-85% 에 도달한다
- **TensorRT-LLM 이 여전히 15-30% 앞선다**
- 이전 비용: **중간**

### 커스텀 CUDA kernel(회사 내부 IP)
- 이것이 **마지막 해자**다
- AI agent 가 프레임워크 변환은 도울 수 있지만 **극한 성능 튜닝은 여전히 사람이 해야 한다**
- 이전 비용: **중간-높음**

## 7. 대형 고객이 AI 변환으로 칩 공급사를 바꿀 가능성

### Microsoft / OpenAI
- Azure ND MI300X v5 는 이미 GPT-3.5/GPT-4 추론을 돌리고 있다
- **OpenAI-AMD 6GW 전략 협약**: MI400 앵커 고객, OpenAI 가 AMD 주식 1.6 억 주 옵션을 보유
- OpenAI 자체 ASIC 은 2026 Q2 prototype, Q4 양산, 2028 년 6GW 로 확대

### Google
- TPU v7 Ironwood 자체 풀스택
- JAX 네이티브, **CUDA 에 의존하지 않는다**

### Meta
- 투 트랙: NVIDIA + 자체 MTIA
- AI 도구가 Llama 의 MTIA 상 kernel 최적화를 가속한다

### AWS
- Trainium 3 / Inferentia
- Anthropic 모델의 Trainium 상 최적화는 AI 코딩 보조에 크게 의존한다

**핵심 발견**: 대형 고객은 AI 코딩으로 "비 NVIDIA 배치"를 가속한다——그러나 NVIDIA 는 여전히 신규 모델 / 신규 부하의 **기본 1 순위**다. AI 코딩의 실제 효과는 **한계 전환 비용을 낮추는 것**이다.

## 8. 장기 5-10 년 해자 변화 예측

### 2026-2028
- AI 코딩 능력이 숙련 GPU 엔지니어 수준에 도달
- ROCm/Triton 성능 격차가 10-15% 로 축소
- Custom ASIC 증가율 44.6% CAGR
- **NVIDIA 추론 점유율: 현재 ~75% → 60-65%**
- NVIDIA 학습 점유율: 90%+ → 80-85%

### 2028-2030
- AI 코딩이 일반적인 kernel 작업에서 중급 인력을 넘어선다
- 자동 최적화가 최상급 수작업의 90% 수준에 도달
- "하드웨어 무관 프로그래밍"의 표준화(Triton, Modular Mojo, PyTorch 2.x compiler)
- **NVIDIA 추론 점유율: 50-55%**
- 학습은 여전히 70%+

### 2030+
- 서술식 프로그래밍: 개발자가 요구를 서술하면 AI 가 하드웨어를 자동 선택 + 최적화
- NVIDIA 의 우위는 "소프트웨어 락인"에서 "하드웨어 단일 세대 성능 + 네트워크"로 완전히 옮겨간다
- 추론 점유율은 **40-50%** 일 수 있다
- 학습 시장은 여전히 default

## 9. AI 코딩 위협에 대한 NVIDIA 의 대응 전략

### 전략 1: AI 로 CUDA 를 강화("AI 의 창으로 AI 의 방패를 친다")
- **Nsight Copilot**(출시 완료): CUDA-aware LLM, ComputeEval 프레임워크 평가
- **Nemotron 3 Ultra**: NVFP4 가 Blackwell 에서 5x 처리량
- **NemoClaw**(GTC 2026 발표): 오픈소스 enterprise agent 플랫폼

### 전략 2: 소프트웨어 스택 확대
- TensorRT-LLM 이 vLLM 대비 15-30% 우위를 지속
- NIM 컨테이너화로 사용 문턱을 낮춘다
- CUDA 13.2 + Rubin 아키텍처의 깊은 결합

### 전략 3: 수직 통합
- DGX Cloud
- Run:ai 인수
- "AI 팩토리" 풀스택 납품

### 전략 4: 하드웨어 우위 지속
- Blackwell → Rubin → Feynman
- 소프트웨어가 따라잡히더라도 하드웨어 단일 세대 성능은 1.5-2x 우위를 지속

### 전략 5: AI 코딩이 실제로는 CUDA 채택을 가속한다(NVIDIA 의 역방향 논점)
- NVIDIA HPC 책임자의 공개 논점: AI agent 는 ROCm 보다 CUDA 를 더 쉽게 쓴다(학습 데이터가 많다)
- **실재하는 역방향 플라이휠**: 인터넷상 GPU 코드의 99% 는 CUDA 다

## 11. 투자 함의

### NVIDIA 의 장기 가치
- **학습 시장**의 해자가 가장 견고하다
- **추론 시장**은 서서히 잠식된다
- 2026 PE 25-30x 는 우려를 이미 partly priced in 했다
- 총매출은 2030 년까지 **여전히 15-20% 연복리 성장을 유지할 수 있다**

### AMD 의 가치
- ROCm 7 + Triton 3.3 + ZLUDA 의 성숙은 **실질적인 질적 변화**다
- OpenAI 6GW 앵커 + MI400 2nm 최초 채택은 구조적 촉매다
- 2026 데이터센터 매출은 2 배가 될 것으로 예상된다

### 핵심 추적 신호
1. AMD MI400 성능 데이터(2026 H2 발표)
2. Microsoft/OpenAI Stargate 자체 ASIC 양산 시점
3. 중국 화웨이 Ascend 의 자국 내 점유율
4. Triton + ROCm 의 PyTorch 메인라인 내 비중
5. Claude Code/GPT-5 의 hyperscaler 내부 AI 코딩 실제 배치 속도

---

**한 문장 결론**: AI 코딩은 CUDA 해자가 직면한 **구조적 장기 위협**이지만 2026 년은 아직 "붕괴" 단계가 아니다——AI 코딩은 "절대적 락인"을 "비용 곡선"으로 바꿔 고객이 성능에 민감하지 않은 시나리오에서 과감히 전환하게 하고, NVIDIA 가 "소프트웨어 장벽" 모델에서 "하드웨어 + 풀스택 AI 팩토리" 모델로 옮겨가도록 강제한다. **NVIDIA 는 장기적으로 여전히 승자다**. 그러나 **최적의 밸류에이션 시점은 이미 지났고**, 향후 5 년 수익률은 지난 5 년보다 뚜렷이 낮을 것이다.
