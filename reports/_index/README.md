# 보고서 색인 구조 설명

`reports/` 아래에는 보고서가 2000건 넘게 있다. 사람과 기계가 모두 찾을 수 있도록 여기서 **색인** 한 층을 관리하며,
보고서 파일 자체는 건드리지 않는다.

## 언어

- 새 보고서와 새 폴더·파일 이름은 **한국어**로 쓴다.
- 기존 중국어 보고서는 그대로 두고 계속 색인한다. 파일명 키워드는 한국어·중국어를 모두 인식한다.
- `index.json`의 `bucket` / `type` 값은 `tools/build_site.py`가 그대로 읽는 내부 키라서 중국어를 유지한다.
  사람이 읽는 `reports/README.md`와 루트 README에서는 한국어 라벨로 바꿔 보여 준다.

## 산출물

| 파일 | 용도 |
|------|------|
| `reports/README.md` | 사람이 읽는 색인: 최근 업데이트 + 기업/테마/대가별 묶음 |
| `reports/index.json` | 기계가 읽는 목록. 스크립트·웹페이지·검색용 |
| 루트 `README.md`의 `REPORTS-INDEX` 블록 | 저장소 첫 화면의 연구 입구. 자동 갱신 |

세 산출물은 모두 `tools/reports_index.py`가 만든다. **손으로 고치지 않는다.**

## 사용법

```bash
# 이번에 공개할 보고서와 첨부를 먼저 스테이징한다 (실제 폴더로 바꿔 쓴다)
git add -- reports/이번연구폴더/

# 그다음 색인을 만든다. 보고서와 세 색인 산출물은 같은 커밋에 넣어야 한다
python3 tools/reports_index.py
git add -- README.md reports/README.md reports/index.json

# 커밋 전/CI 점검: 오래됐는지만 확인하고 파일은 쓰지 않는다
python3 tools/reports_index.py --check
```

색인은 Git 스테이징 영역에 있는 파일만 싣는다. 방금 `git add` 한 새 보고서도 포함된다.
미추적 파일, `.gitignore`로 무시되는 파일, `git add -N`만 한 로컬 파일은 실리지 않는다.
새 보고서를 스테이징에서 빼면 색인을 다시 만들어야 한다. 색인만 커밋하고 보고서 원문을 빠뜨리지 않는다.

색인에는 링크가 있는데 GitHub에서 404가 나면 먼저 `git status --short`와
`git ls-files -- reports/해당폴더/`를 확인한다. 원고가 로컬에 남아 있으면 위 순서대로 보고서와 색인을 다시 커밋한다.
원고가 현재 체크아웃에 없으면 원래 작업 폴더나 백업에서 찾아야 한다. 색인만으로는 본문을 복구할 수 없다.

## 메타데이터의 출처

스크립트는 다음 우선순위로 보고서의 제목·날짜·유형·소속을 추정한다.

1. **파일의 YAML front-matter** (선택, 최우선)
2. **파일명**: `회사-주제-YYYYMMDD.md`의 8자리 날짜
3. **본문**: 앞 15줄 안의 `2026-09-07` / `2026년 9월 7일` / `2026年9月7日`
4. **git 최근 커밋 날짜**

새 보고서를 쓸 때 **파일명에 `-YYYYMMDD` 접미를 붙이고 본문 첫 줄을 `# 제목`으로 쓰면 따로 할 일이 없다.**

추정 결과를 덮어써야 하면 파일 맨 앞에 front-matter를 넣는다.

```markdown
---
title: 핀둬둬 2026Q2 실적 정독
date: 2026-08-25
type: 실적
---

# 본문 제목
```

`type`에 쓸 수 있는 값은 아래 표의 한국어 라벨 또는 내부 키다. 한국어 라벨로 쓰면 스크립트가 내부 키로 바꿔 저장한다.

| 한국어 라벨 | 내부 키 (`index.json`) | 파일명에서 인식하는 한국어 키워드 |
|------|------|------|
| 연구 | `研究` | (기본값) |
| 실적 | `财报` | `earnings`, `실적`, `분기보고`, `반기보고`, `사업보고`, `컨퍼런스콜`, `q1`~`q4` |
| 심층시리즈 | `深度系列` | `제대로알기`, `심층연구`, `deep-dive` |
| 비교 | `横评对比` | `비교`, `대결`, `로테이션`, `vs` |
| 밸류·비중 | `估值仓位` | `밸류에이션`, `배당률`, `켈리`, `비중`, `터미널밸류`, `valuation` |
| 조직·경영 | `组织管理` | `경영진`, `조직`, `management` |
| 스크리닝 | `筛选` | `스크리닝`, `후보풀`, `퍼널`, `funnel`, `screen` |
| 공식계정 | `公众号` | `공식계정`, `wechat` |
| 초안 | `底稿` | `연구초안`, `초안`, `독자리뷰`, `검증기록` |

## 소속 분류

최상위 폴더가 어느 분류에 들어가는지는 `reports/_index/config.json`이 정한다.

- `companies`: 기업 폴더 (기본값. 새 기업 폴더는 등록하지 않아도 정상적으로 색인된다)
- `themes`: 여러 기업에 걸친 테마, 산업 체인 연구
- `masters`: 대가 방법론 연구
- `screens`: 스크리닝과 추론의 **중간 산출물**(후보풀 등). 색인에는 폴더와 건수만 보이고 하나씩 나열하지 않는다
- `aliases`: 한 회사의 여러 폴더명을 하나의 대표 이름으로 묶는다. 예: `Alibaba` → `阿里巴巴`

테마나 스크리닝 풀 폴더를 새로 만들면 `config.json`의 해당 배열에 한 줄 추가한다. 빠뜨리면 기업으로 처리된다.

### 한국어 폴더와 기존 중국어 폴더 묶기

새 보고서는 한국어 회사명 폴더에 쓴다(예: `reports/텐센트/`). 같은 회사의 기존 중국어 폴더(`reports/腾讯/`)가 있으면
`aliases`에 다음처럼 한 줄 추가해 색인에서 한 그룹으로 묶는다. 기존 폴더와 파일은 옮기거나 이름을 바꾸지 않는다.

```json
"aliases": {
  "腾讯": "텐센트"
}
```

## 완성 보고서만 싣고 중간 산출물은 싣지 않는다

`reports/README.md`와 루트 README에는 **완성 보고서**만 나온다. 증빙 대장, 감사·검증 설명, 재계산 초안,
출처 목록, 시리즈 안내, Agent 조사 노트 같은 중간 산출물은 모두 `초안`(내부 키 `底稿`)으로 표시해 사람이 읽는 색인에 넣지 않고
`index.json`에만 남긴다(`type`이 `底稿`, 맨 위에 `published` / `drafts` 건수가 있다).

판정 규칙은 `config.json`의 `drafts` 항목에 있으며, 세 가지 중 하나라도 걸리면 초안이다.
한국어 규칙과 기존 중국어 규칙이 함께 들어 있다.

- `dirs`: 경로에 이 폴더명이 있다 (`evidence`, `증빙`, `research`, `초안`, `data`, `sources` 등)
- `dir_suffixes`: 폴더명에서 날짜를 뗀 뒤 `증빙` / `검증` / `감사` / `초안`으로 끝난다
- `file_patterns`: 파일명 정규식 (`audit`, `sources`, `출처목록`, `감사설명`, `검증기록`, `재무표`, `초안`, `시리즈안내` 등)

파일명에 `공식계정`(또는 `公众号`)이 들어 있으면 초안으로 보지 않는다. 잘못 판정되면 파일 맨 앞 front-matter의 `type:`으로 덮어쓴다.
예를 들어 완성본인 "재무 품질 감사 보고서"에는 `type: 연구`를, 숨기고 싶은 파일에는 `type: 초안`을 쓴다.

새 연구 폴더의 약속: **정식 보고서는 폴더 첫 단계나 기업 하위 폴더에 두고, 증빙·로그·스크립트·재계산 결과는
`evidence/` 또는 `증빙/` 하위 폴더에 둔다.** 이렇게 하면 등록하지 않아도 자동으로 구분된다.

## 개인정보

스크립트는 Git 스테이징 영역의 경로 목록으로 공개 색인의 범위를 제한한다. Git에 넣지 않은 로컬 파일
(`.gitignore`로 무시되는 `reports/portfolio-latest.md` 포함)은 읽지도 않고 색인에 쓰지도 않는다.
Git을 쓸 수 없으면 생성을 중단하며, 로컬 파일 전체를 훑는 방식으로 되돌아가지 않는다.
`git add -f`로 명시적으로 추가한 파일은 공개 대상으로 본다.
