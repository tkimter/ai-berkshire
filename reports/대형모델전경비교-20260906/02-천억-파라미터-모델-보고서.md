## 가장 중요한 결론

**천억 파라미터라고 해서 매번 천억 파라미터를 계산하는 것은 아니며, 작은 모델보다 더 강하다는 뜻도 아니다.** 요즘의 많은 대형 모델은 전문가 혼합 아키텍처(MoE)를 채택한다. 가중치 총량은 저장 규모를 결정하고, 매번 활성화되는 파라미터는 그 일부에 그친다. 동시에 현대의 사후 학습, 데이터, 도구, 추론 예산은 파라미터가 더 작은 모델이 특정 과제에서 더 큰 모델을 넘어서게 하기에 충분하다.

**오픈소스 상태는 구체적인 모델과 버전별로 판단해야 한다.** DeepSeek-V4, Qwen3.5, Hy3, Command A+, K-EXAONE 2.0은 비교적 관대한 가중치 라이선스를 갖고 있다. Kimi K3, Qwen3.8-2.4T, GLM-5.3, MiniMax M3 등에는 서로 다른 상업 조건이 붙어 있다. 더 이른 DeepSeek-V3 초판도 이후 V3.1/V3.2의 MIT 라이선스로 자동 처리할 수 없다. 항목별 출처는 아래 목록을 참조한다.

본 목록은 확인 가능한 주요 제품, 오픈 가중치, 역사적 연구 모델을 다루며, 전 세계의 모든 학습 실험, 병합 모델, 커뮤니티 파인튜닝을 망라한다고 주장하지 않는다. 파라미터가 공개되지 않은 플래그십을 "조 단위 모델"로 추측하지 않는다.

## 계수 규칙: B, T와 활성 파라미터부터 구분한다

| 표현 | 환산 또는 의미 |
|---|---|
| 1B 파라미터 | 10억 파라미터 |
| 100B 파라미터 | 1,000억 파라미터, 즉 본문의 "천억" 기준선 |
| 1T 파라미터 | 1조 파라미터, 즉 1,000B |
| 235B-A22B | 총 파라미터 약 2,350억, token당 활성 약 220억 |
| 128B 밀집 모델 | 순전파마다 백본 파라미터를 사실상 전부 사용한다. MoE식으로 소수의 전문가만 고르는 것이 아니다 |
| 활성 파라미터 | token마다 호출되는 모델 부분. VRAM 점유량이 아니고, 정밀한 FLOPs나 응답 속도도 아니다 |

본문의 주 표는 개발자가 공개한 모델 규모를 우선 채택한다. 부가 예측 층(MTP), 시각 인코더, 임베딩 층, 양자화 관련 텐서가 산입되는지는 출처마다 다를 수 있으므로 "약", "백본", "저장소 텐서 집계" 등의 라벨을 남긴다. 학습 말뭉치의 tokens 수, 컨텍스트 길이, 파라미터 개수는 서로 다른 세 가지다.

## 이 플래그십들의 파라미터는 지어낼 수 없다

"똑똑하니까 수조 파라미터일 것이다"는 증거가 되지 못한다. "API가 싸니까 모델이 분명 작을 것이다"도 성립하지 않는다. 가격은 하드웨어 효율, 스케줄링, 양자화, 캐시, 보조금, 상업 전략의 영향도 받는다.

| 비공개 또는 가중치 개방 미확인 | 현재의 GPT/Claude/Gemini, Grok 4.6, Muse, Seed2.1, Nova | 제품/API는 쓸 수 있다. 이를 근거로 가중치를 직접 얻어 배포할 수는 없다 |

가장 핵심적인 자체 라이선스 조항:

- **Kimi K3**: MaaS 운영자 및 관계사의 연속 12개월 총매출이 2,000만 달러를 넘으면 상업적 사용에 별도 계약이 필요하다. 별도로 규모에 따른 저작자 표시 요구와 내부 사용, 공식 채널 예외가 있다. [원문](https://huggingface.co/moonshotai/Kimi-K3/blob/main/LICENSE)
- **Qwen3.8**: MaaS 또는 독립 AI 코딩/오피스 어시스턴트 사업을 운영하고 본인 및 관계사의 연속 12개월 합산 총매출이 5,000만 달러를 넘으면 별도 라이선스가 필요하며, 조문은 내부 사용 예외를 규정한다. 또 다른 월간 활성 사용자/월 매출 기준선에 도달하면 모델명을 표시해야 한다. [원문](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B/blob/main/LICENSE)
- **GLM-5.3**: MaaS 운영자 및 관계사의 연속 12개월 합산 매출이 100억 달러를 넘으면 상업적 사용 전에 안전 심사가 필요하다. Flash판은 MIT이며 혼동해서는 안 된다. [원문](https://huggingface.co/zai-org/GLM-5.3/blob/main/LICENSE)
- **MiniMax M3**: 상업적 사용에는 저작자 표시와 통지가 필요하고, 관련 제품/서비스의 연 매출이 2,000만 달러를 넘으면 사전 서면 승인이 필요하다. 용도 제한이 있다. [원문](https://huggingface.co/MiniMaxAI/MiniMax-M3/blob/main/LICENSE)
- **Mistral Medium 3.5 / Devstral 2**: 직전 한 달 글로벌 연결 매출이 2,000만 달러를 넘는 회사/고용주는 Modified MIT에 근거해 직접 사용할 수 없고, 상업 라이선스 등의 조치가 필요하다. [Medium 라이선스](https://huggingface.co/mistralai/Mistral-Medium-3.5-128B/blob/main/LICENSE), [Devstral 라이선스](https://huggingface.co/mistralai/Devstral-2-123B-Instruct-2512/blob/main/LICENSE)

이것은 읽기 요약이며 완전한 라이선스를 대신하지 않는다. 엄밀한 의미의 오픈소스 AI는 모델 수정에 필요한 코드, 파라미터, 데이터 정보 등의 요건도 충족해야 한다. 그래서 본 보고서는 "관대한 라이선스의 오픈 가중치", "조건부 오픈 가중치" 같은 구체적 표현을 쓴다. [OSI 정의](https://opensource.org/ai/open-source-ai-definition).

## 천억 모델에는 결국 얼마나 큰 메모리가 필요한가

모든 파라미터를 같은 정밀도로 저장한다면, **가중치만의** 이론적 용량은 다음과 같다.

`파라미터 개수 × 파라미터당 비트 수 ÷ 8`.

아래 표는 십진 GB이며, 1GB = 10^9 바이트다. BF16/FP16은 2바이트, 8 bit는 1바이트, 4 bit는 0.5바이트다. 표의 양자화는 가정이며, 모든 모델에 해당 정밀도의 사용 가능하고 품질이 동등한 구현이 있다고 보장하지 않는다.

| 파라미터 규모 예시 | 16 bit 가중치 GB | 8 bit 가중치 GB | 4 bit 가중치 GB |
|---|---:|---:|---:|
| 100B 기준선 | 200 | 100 | 50 |
| 117B, gpt-oss 주 규모 | 234 | 117 | 58.5 |
| 122B | 244 | 122 | 61 |
| 196B | 392 | 196 | 98 |
| 320B | 640 | 320 | 160 |
| 397B | 794 | 397 | 198.5 |
| 428B | 856 | 428 | 214 |
| 671B | 1,342 | 671 | 335.5 |
| 753B 예시 기준 | 1,506 | 753 | 376.5 |
| 1.02T | 2,040 | 1,020 | 510 |
| 1.6T | 3,200 | 1,600 | 800 |
| 2.4T | 4,800 | 2,400 | 1,200 |
| 2.8T | 5,600 | 2,800 | 1,400 |

위 수치는 프로젝트의 정밀 산술 도구로 재검증했다. 구매 사양이 아니다. 실제 배포에는 KV cache 또는 선형 어텐션 상태, 양자화 scale, 활성값, 통신 버퍼, 프레임워크 작업 공간, 메모리 여유분을 더해야 한다. MoE의 서로 다른 전문가는 서로 다른 token에서 호출되므로, **"활성 13B"만 보고 284B 모델에 13B 가중치만큼의 VRAM을 준비해서는 안 된다**. 가중치 일부를 CPU 메모리, 디스크에 두거나 노드 간에 나눠 올릴 수도 있지만, 속도와 동시성은 메모리 대역폭과 인터커넥트의 영향을 받는다.

예를 들어 gpt-oss-120b의 공식 설명은 네이티브 양자화 방안으로 단일 80GB GPU에서 실행할 수 있다고 한다. 이것이 모든 120B 모델의 모든 정밀도, 컨텍스트, 동시성에 같은 구성을 쓸 수 있다는 뜻은 아니다. Qwen3-235B의 모델 카드는 약 1M 컨텍스트에 대해 총 GPU 메모리 약 1,000GB라는 예시 요구 사항을 제시하며, 캐시와 실행 구성의 영향이 매우 크다는 것을 보여 준다. [gpt-oss 모델 카드](https://huggingface.co/openai/gpt-oss-120b), [Qwen3 긴 컨텍스트 설명](https://huggingface.co/Qwen/Qwen3-235B-A22B-Instruct-2507).

## 파라미터 보고서에서 얻는 선택의 결론

주로 API로 쓴다면 과제 성공률, 비용, 지연을 우선 비교한다. 벤더가 파라미터를 공개하지 않았다고 해서 평가에 지장이 생기지는 않는다. 자체 배포하려면 라이선스와 하드웨어 예산을 먼저 고르고, 그다음에 모델 능력을 거른다. 천억급을 시도해 보고 싶다면 Kimi K3이나 Qwen3.8 같은 수조 파라미터 모델에서 시작할 필요가 없다. 117B에서 196B의 희소 모델이 이미 다양한 추론 및 도구 과제 경로를 제공한다.

**모델 능력, 파라미터 규모, 다운로드 가능성, 상업적 허가는 각각 따로 판단해야 한다.** 서로 관련은 있지만, 어느 하나도 나머지 셋을 대신할 수 없다.

## 검증과 한계

파라미터는 개발자의 모델 카드 또는 원본 논문에서 가져왔다. GLM-5.2/5.3 등은 공식 저장소 메타데이터를 추가로 점검했다. 라이선스는 구체적인 가중치 저장소의 본문 또는 명시된 링크를 기준으로 하며, 웹페이지의 "open source" 홍보 문구만 봐서는 안 된다. 계정으로 약관을 수락해야 하는 저장소는 공개 페이지와 메타데이터만 읽었고, 사용자를 대신해 라이선스를 수락하지 않았다.

이번에는 모델 추론을 실행하거나, 가중치 전체를 내려받거나, 학습 재현 가능성을 검증하지 않았다. 일부 모델의 정밀한 활성량, 최신 API와 공개 가중치의 대응 관계는 여전히 공개되지 않았으며, 이 공백은 그대로 남겼다. 역사적 항목은 규모의 변천을 이해하는 데 쓰며, 현 세대 능력 순위표에 그대로 넣을 수 없다. 전체 검증 기록은 [감사 설명](</Users/linxuan/ai-berkshire/reports/대형모델전경비교-20260906/03-核查记录.md>)을 참조한다.
