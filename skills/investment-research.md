# 투자 연구: 버핏-멍거-돤융핑-리루 4대 거장 종합 분석 프레임워크

$ARGUMENTS 에 대해 체계적인 투자 연구 분석을 수행한다.

## 연구 프레임워크

버핏, 멍거, 돤융핑, 리루 네 투자 거장의 방법론을 바탕으로, 아래 일곱 개 모듈을 순서대로 수행한다:

### 사전 단계: AI 연구 편향 자각(반드시 수행)

연구를 시작하기 전에 해당 회사의 "AI 연구 가능성"을 평가하고 잠재적인 데이터 편향을 식별한다:

**정보 풍부도 등급**:
| 등급 | 특징 | AI 연구의 함정 | 대응 전략 |
|------|------|-----------|---------|
| A급(정보 풍부) | 상장한 지 오래됨, 증권사 커버리지 많음, 언론 보도 밀집 | 컨센서스가 지나치게 강해 AI 출력이 시장 가격에 수렴하고 alpha가 제한적이다 | 반면 검증에 집중한다: 똑똑한 사람들은 왜 사지 않는가? 간과된 리스크는 무엇인가? |
| B급(정보 보통) | 상장 1-3년, 커버리지 제한적, 일부 데이터는 추산 필요 | AI가 "합리적 추측"으로 공백을 메워, 완전해 보이지만 실제로는 거짓 확실성이 된다 | 추산 데이터마다 신뢰도를 표기하고 "근거 있는 추산"과 "근거 없는 채우기"를 구분한다 |
| C급(정보 희소) | 갓 상장/비인기 종목/신흥시장, 커버리지 거의 없음 | AI가 자료 부족 때문에 지나치게 보수적이 되어 "잘 안 보인다=나쁘다"로 오판한다 | 제1원리로 질문하고(아래 참조), 제한된 정보에서 사업의 본질을 뽑아낸다 |

**C급 회사의 제1원리 연구법**:
공개 자료가 부족할 때는 "완전해 보이는" 보고서를 짜깁기하려 하지 말고, 아래의 근본 질문에 집중한다:
1. 고객은 누구인가? 왜 돈을 내는가? 대체 선택지가 있는가?
2. 재구매는 무엇이 이끄는가? 습관인가, 락인인가, 지속적인 새 가치 창출인가?
3. 경쟁자가 100억을 들이면 이 사업을 복제할 수 있는가?
4. 경영진은 어떤 핵심 의사결정을 했는가? 그 결정은 어떤 판단력과 가치관을 보여주는가?

**편향 자가 점검 체크리스트**(연구 내내 경계한다):
- [ ] 내가 느끼는 "확실성"은 사업의 본질에서 오는가, 자료의 양에서 오는가?
- [ ] 이 회사의 자료량을 절반으로 줄여도 내 결론은 그대로인가?
- [ ] AI가 출력한 분석이 시장 컨센서스와 지나치게 닮지 않았는가? 그렇다면 내 정보 우위는 어디에 있는가?
- [ ] "공개 자료는 적지만 사업의 본질은 매우 좋을" 가능성이 과소평가되지는 않았는가?

정보 풍부도 등급 결과를 보고서 첫머리에 적고, 최종 결론에서 "AI 연구 신뢰도"와 "실제 투자 확실성"의 차이를 명시한다.

### 1단계: 데이터 수집

> **데이터 출처 규범**: `skills/financial-data.md` 참조. 모든 재무 데이터는 독립된 두 출처에서 가져와야 하며, 오차가 1%를 넘으면 표시한다.
> - 미국 주식: macrotrends(주) + stockanalysis(부)
> - 홍콩 주식: aastocks(주) + macrotrends ADR(부)
> - A주: 东方财富(주) + 巨潮资讯(부)

Task 도구로 백그라운드 Agent를 띄워 웹에서 아래 데이터를 수집한다:

1. 매출 구조: 최근 회계연도 및 최근 4개 분기의 부문별 매출, 증가율, 매출총이익률
2. 재무 지표: 최근 5년 매출, 순이익, 매출총이익률, 영업이익률, 잉여현금흐름, 현금 보유액
3. 경쟁 구도: 시장점유율, 주요 경쟁사 비교
4. 비즈니스 모델과 해자: 핵심 경쟁우위의 원천
5. 기술 역량: 핵심 기술 스택, 연구개발 투자
6. 경영진: 창업자/CEO 이력, 지분율, 핵심 의사결정 기록
7. 산업 전망: TAM(전체 유효 시장), 성장 전망
8. 리스크 요인: 지정학, 규제, 공급망 등
9. 현재 밸류에이션: 시가총액, PE, PS, PEG, EV/Revenue
10. 강세·약세 양측의 핵심 논점

#### 데이터 교차 검증(반드시 수행, 금융 엄밀성 도구 사용)

데이터 수집이 끝나면 **반드시 `tools/financial_rigor.py`를 호출해 핵심 데이터를 프로그램으로 검증**하고, LLM 암산 오차를 차단한다.

**반드시 검증할 데이터 포인트**:
- 총 발행주식수(거래소, Yahoo Finance, StockAnalysis 등 최소 2개 출처에서 확인)
- 현재 주가와 시가총액(**주가×총 발행주식수를 직접 계산해 보고서의 시가총액과 대조하고, 단위 오류를 막는다**)
- 최근 회계연도 매출과 순이익(회사 연차보고서 + 최소 1개 제3자 출처에서 확인)
- 현금 보유액과 순현금(현금+단기투자-총부채, 기준 차이에 주의)
- 경영진 지분율(경제적 지분과 의결권을 구분하고, AB주 구조에 주의)

**강제 검증 절차(Bash로 도구 호출)**:

Step 1 — 시가총액 검산(부동소수점이 아닌 정밀 십진 연산):
```bash
python3 tools/financial_rigor.py verify-market-cap \
  --price {주가} --shares {총발행주식수} --reported {보고서시가총액} --currency {통화}
```

Step 2 — 핵심 데이터 다중 출처 교차 검증:
```bash
python3 tools/financial_rigor.py cross-validate \
  --field {필드명} --values '{"출처1": 수치, "출처2": 수치}' --unit {단위}
```
매출, 순이익, 현금 보유액에 대해 각각 실행한다.

Step 3 — 밸류에이션 지표 정밀 검산(PE/PB/ROE/FCF Yield 등):
```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {주가} --eps {EPS} --bvps {주당순자산} --fcf-per-share {주당FCF} --dividend {주당배당금}
```

**검증 규칙**:
1. 핵심 데이터 포인트마다 최소 2개의 독립 출처
2. 출처 간 차이가 발견되면 회사 연차보고서/거래소 데이터를 우선 채택하고 차이의 원인을 적는다
3. **계산이 들어가는 모든 데이터는 도구로 검산해야 하며, LLM 암산은 금지한다**
4. 도구 출력 결과는 보고서 부록 "핵심 데이터 교차 검증 기록"에 그대로 넣는다
5. 도구가 ❌ 편차 과대를 보고하면 원인을 규명한 뒤에야 분석을 계속할 수 있다

**흔한 오류 예방**:
- 시가총액 단위: 억 홍콩달러 vs 억 위안화 vs 억 달러, 0을 하나 빠뜨리거나 더 쓰기 쉽다
- FCF 기준: 출처마다 자본적 지출의 정의가 다를 수 있다(리스, 인수 포함 여부 등)
- 부채 기준: 운용리스 부채 포함 여부
- 지분율: AB주 회사의 경제적 지분 ≠ 의결권

#### 장기 할인 밸류에이션(10년 척도, 반드시 수행)

**역할 분담(강제 제약, 혼용 금지):**

| 도구 | 답하는 질문 | 해당하지 **않는** 것 |
|---|---|---|
| **3년 3개 시나리오**(`financial_rigor.py three-scenario`) | **"비싼가 아닌가"**——내재가치/과거/동종업계 대비 현재 가격에 안전마진이 있는가 | 집중 투자 판정, 단독 거부권 |
| **10년 할인**(`terminal_value.py`) | **비중 스트레스 테스트**——명시한 r 하에서 10년 기대 IRR이 자본비용을 감당하는가. **포트폴리오 비중 상한/비중을 더 키울 가치가 있는지**에 대한 스트레스 테스트로 쓴다 | **매수/보유/회피에 대한 유일한 거부권** |

3년 3개 시나리오는 "비싼가 아닌가"에 답하고, 10년 할인은 "명시한 할인율 하에서 비중을 얼마나 무겁게 실을 수 있는가"에 답한다. **10년 기준 IRR이 r보다 낮으면 비중 제안만 조일 수 있고, 그것만으로 최종 결정을 회피/관망으로 바꿔서는 안 된다.** 최종 매수/보유/회피는 사업의 질, 해자, 경영진, 리스크, 문명 추세, 밸류에이션 **여섯 개 차원을 나란히 놓고** 도출해야 하며, 10년 모델은 밸류에이션 차원 안의 스트레스 테스트 입력일 뿐이다.

> 방법론의 일관성이 "r을 낮춰서 사는 것"보다 우선한다: 민감도와 반전 점검은 "결론이 사는 것이 회사인지 할인율인지"를 드러내기 위한 것이다. thesis나 주관적 매수 충동에 맞추려고 r을 통화별 합리 구간 밖으로 조정하는 것은 **금지**한다.

**10년 IRR이나 종말가치 배수를 제시하는 연구는 반드시 이 절차를 거치며**, `tools/terminal_value.py`를 사용한다.

종말가치 배수의 합법적인 출처는 단 하나, 영구성장 모형뿐이다. **동종업계 유추는 허용하지 않는다**:

$$PE_{종말가치} = \frac{1 - g/ROIC}{r - g}$$

> "디아지오가 13배이니 마오타이에 16배를 준다"는 순환 논증이다: 남의 오늘 가격으로 내가 가정한 가격이 합리적이라고 증명하는 것이다. 오늘 시장 전체가 비싸면, 유추법은 그 비쌈을 고스란히 10년 뒤로 옮겨 놓는다.

**Step 1 — 세 가지 입력을 정하고 하나씩 이유를 적는다(이 단계는 전부 판단이지 계산이 아니며, 반드시 보고서에 밝혀야 한다):**

| 입력 | 정하는 방법 | 흔한 오류 |
|---|---|---|
| **r** 자본비용 | 무위험이자율 + β × ERP. **통화는 현금흐름과 일치해야 한다**: 위안화 기준 6%–9%(주로 8% 사용), 달러/홍콩달러 기준 9%–11.5%(주로 10% 사용) | 국채 금리를 따라간다. 중국 국채 1.70%로 할인하면 PE가 50배를 넘는데, 그것은 밸류에이션이 아니라 편향의 증폭이다 |
| **ROIC** 정상상태 증분 자본수익률 | 기존 자본 ROIC(재무제표에 잡히지 않는 무형 해자를 포함해 높게 나옴)와 배당에서 역산한 내재 증분 ROIC(capex 수익을 0으로 가정해 낮게 나옴) 사이에 둔다 | 기존 자본 ROIC를 그대로 쓴다. 새로 투자하는 돈마다 위챗을 구축할 때의 수익을 복제할 수 있다고 가정하는 것과 같다 |
| **g** 영구성장률 | **향후 10년 성장률이 아니다**(그것은 이미 종말가치 이익에 들어 있다). 종말가치 연도 이후 영원까지의 성장률이다. 절대 상한은 장기 명목 GDP: 위안화 기준 기본 구간 ≤2%, 달러 기준 ≤4% | 달러의 g를 위안화의 r과 짝짓는다. 명목 성장 3%는 미국에서는 실질 0.5%(보수적)이지만 중국에서는 실질 2%(공격적)이다 |

**g는 r에 따라 변하지 않는다**——g는 종말가치 연도 이후의 경제에 대한 판단이고, r은 내가 요구하는 수익률이다. 서로 독립된 두 가지다. 민감도 분석에서는 r만 움직인다.

**Step 2 — 세 가지 강제 제약 통과 검사(통과하지 못하면 밸류에이션을 보고서에 쓸 수 없다):**

```bash
python3 tools/terminal_value.py audit \
  --currency {CNY|USD|HKD} --r {자본비용} --roic {정상상태ROIC} \
  --g {비관g},{기준g},{낙관g} --rf {무위험이자율} --beta 1.0 \
  --discrete-risks "{리스크명}:{시나리오|테일구간|확률|미모델링},..."
```

세 가지 검사의 내용과 반려 조건(`--discrete-risks`의 귀속 값은 한국어로 적는다: `시나리오`, `테일구간`(`테일 구간`도 인식), `확률`은 통과, `미모델링`은 경고, `할인율`은 반려):

| # | 검사 | 반려 조건 |
|---|---|---|
| **C1** | **r과 g는 같은 통화여야 한다** | r이 다른 통화의 구간에 들어가거나, 기준 구간의 g가 자국 통화 상한을 넘는 경우. 도구가 "이것은 USD의 수준이다——r은 자국 통화를 쓰고 g는 외화를 썼다"고 직접 짚어준다 |
| **C2** | **분모 r−g ≥ 5%포인트** | 어느 한 구간이라도 5pct에 못 미치는 경우. 분모가 좁을수록 g가 조금만 움직여도 밸류에이션이 뒤집힌다. 분모 ≤0이면 곧바로 모델 무효로 판정한다. 상방/하방 시나리오가 꼭 필요하면 `--upside-only`를 붙여 명시적으로 선언하되, 보고서에 "이것은 시나리오이지 밸류에이션이 아니다"라고 반드시 적는다 |
| **C3** | **이산 리스크는 r이나 β에 넣을 수 없다** | 어느 리스크든 귀속을 `할인율`/`r`/`beta`로 적으면 일률적으로 반려한다. 상장폐지, VIE 무효화, 지정학적 공급 차단, 규제 강타는 반드시 `시나리오` 또는 `테일구간`에 귀속한다. β가 1.0에서 벗어나면 반드시 `--beta-justification`을 제시한다 |

**C3가 강제 제약인 이유**: r을 3%포인트 올리면 10년차 현금흐름에 대한 벌점이 1년차의 2.6배가 된다. 그런데 상장폐지 리스크는 대체로 균등하거나 오히려 앞쪽에 몰린 연간 위험률이다. **할인율로 이산 리스크를 처리하면 리스크의 시간 분포를 체계적으로 거꾸로 만든다.** 올바른 방법은 테일 시나리오 구간을 따로 두고 확률을 부여하는 것이다.

**C1/C2/C3의 전체 논증은** `reports/7개회사-10년-투자가치-비교-확실성조정후수익-20260814.md` 3.4–3.6절 참조——세 가지 모두 그 보고서가 실제로 빠졌던 함정이다.

**Step 3 — 수치 산출(통과한 뒤에만 실행할 수 있다):**

```bash
# 단일 시점 엑시트 PE, 전체 산식 출력(유보율/분자/분모를 모두 전개해 보고서 인용에 편리)
python3 tools/terminal_value.py pe --roic {ROIC} --g {g} --r {r}

# IRR을 처음부터 계산
python3 tools/terminal_value.py irr \
  --profit {종말가치연도이익} --mcap {오늘시가총액} --pe {엑시트PE} \
  --years 10 --payout {배당수익률-희석률}
```

여러 회사를 횡단 비교할 때는 파라미터를 JSON으로 작성해 `--config`로 넘기고, `table` / `sweep` / `check`를 사용한다.

**Step 4 — 보고서에 반드시 적어야 하는 다섯 가지:**

1. **r 값, 통화, 그리고 짝이 되는 g 상한**. r을 밝히지 않고 IRR을 보고하면 자기 선호를 보고하는 것이다.
2. **r±2pp 민감도와 결론의 반전 여부(강제 제약, 매수/보유/회피를 쓰기 전에 반드시 실행)**:
   ```bash
   # 내장 프리셋 회사(텐센트/알리바바/핀둬둬/구이저우마오타이/팝마트/메이퇀/MiniMax — 도구에 등록된 이름 그대로 입력)
   python3 tools/terminal_value.py flip \
     --name {프리셋회사명} --r {기준r} --delta 0.02 \
     --currency {CNY|USD|HKD} --g-shift {통화평행이동} --rf {무위험이자율}

   # 신규 회사: 인라인 파라미터(필드 의미는 아래 --config와 동일)
   python3 tools/terminal_value.py flip \
     --name {회사명} --roic {정상상태ROIC} --g {비관g},{기준g},{낙관g} \
     --p {비관확률},{기준확률},{낙관확률} --irr10={비관},{기준},{낙관} --k {배당수익률-희석률} \
     --r {기준r} --delta 0.02 --currency {CNY|USD|HKD} --g-shift {통화평행이동} --rf {무위험이자율}

   # 신규 회사: 또는 JSON으로 작성해 --config로 전달(여러 회사를 한 파일에 쓸 수 있고, --name은 그중의 키를 가리킨다)
   python3 tools/terminal_value.py flip --config {설정.json} --name {회사명} \
     --r {기준r} --delta 0.02 --currency {CNY|USD|HKD} --g-shift {통화평행이동} --rf {무위험이자율}
   ```
   `--config` 파일 형식(내장 프리셋 필드와 동일하며, `k`는 생략 가능, 기본값 0):
   ```json
   {
     "어떤회사": {
       "roic": 0.18,
       "g": [0.015, 0.030, 0.040],
       "p": [0.35, 0.50, 0.15],
       "irr10": [-2.0, 8.0, 14.0],
       "k": 0.01
     }
   }
   ```
   | 필드 | 의미 |
   |---|---|
   | `roic` | 2036년 정상상태 증분 ROIC(Step 1의 판단값), 소수 |
   | `g` | 비관/기준/낙관 3개 구간의 영구성장률(평행이동 전의 원래 기준), 소수. 통화 환산은 `--g-shift`로 명시적으로 표현한다 |
   | `p` | 3개 구간의 확률, 합은 1 |
   | `irr10` | r=10%, 원래 g 하에서 3개 구간의 10년 IRR(백분율, 예: 8.0은 8%). 다른 r로 환산하는 기준점이다. Step 3의 `pe` + `irr`로 r=10%에서 구간별로 계산한다. 인라인에서는 등호 표기 `--irr10=-2,8,14`를 쓴다(첫 항이 음수일 때 필수) |
   | `k` | 배당수익률 − 희석률, 연율 소수 |

   - **`--currency`는 필수**이며, Step 2 audit와 같은 통화를 쓴다. 도구는 `CURRENCY_BANDS`(위안화 6%–9%, 달러/홍콩달러 9%–11.5%, audit C1과 동일)에 따라 구간마다 판정한다: **구간 밖의 구간은 "구간 밖, 참고용"(도구 출력 그대로)으로 표시되고 반전 판정에 참여하지 않는다**. 기준 r 자체가 구간 밖이면 곧바로 【반려】된다.
   - `r−2pp` / `r` / `r+2pp` 3개 구간의 기대 IRR과, 각 구간이 "기대 IRR ≥ r"(자본비용 감당) 기준으로 스트레스 테스트를 통과하는지를 반드시 함께 보고한다. 구간 밖의 구간은 "참고용" 표시를 그대로 옮겨 적고, 구간 밖 구간의 "통과"로 매수를 논증해서는 **안 된다**.
   - **반드시 명시적으로 적는다: 결론이 통화별 합리 구간 안에서 Δr에 따라 반전되는가.** ±2pp 양쪽이 모두 구간 밖에 떨어지면(도구가 "구간 안에서는 기준 구간 하나만 판정에 참여한다"고 알려준다), `--delta 0.01`로 구간 안에서 한 번 더 점검하고 두 결과를 모두 보고서에 적는다. 반전된다면 보고서에 "본 결론은 할인율에 민감하므로 비중 제안을 한 단계 낮춰야 한다. 단일 기준 r 하의 미통과를 매수 거부권으로 삼아서는 안 된다"라고 밝혀야 한다.
   - 여러 회사를 횡단 비교할 때는 별도로 `sweep`으로 순위의 안정성을 검증한다. 절대 수치는 r에 좌우되며, 순위야말로 견고한 결론이다.
3. **구간별 r−g 분모 폭**. 5pct 미만인 것은 반드시 "시나리오 참고용"이라고 표시한다.
4. **모델링하지 않은 이산 리스크 목록**(audit에서 `미모델링`으로 표시한 것). "한계" 장에 적는다.
5. **이견 대조 블록(Reconciliation, 조건부 강제)**: 10년 스트레스 테스트 결론(r 대비 기대 IRR)이 3년 3개 시나리오의 "비싼가 아닌가", 또는 저장소 내 기존 thesis / 본 보고서 앞 여섯 단계의 종합 성향과 **방향이 일치하지 않을** 때, 보고서는 **반드시** 「밸류에이션 이견 대조」 절을 따로 두고 다음을 분명히 적는다:
   - 이견의 양측이 각각 무엇에 근거하는가(3년 안전마진 vs 10년 r 하의 IRR);
   - 어느 쪽이 **가격 판단**이고 어느 쪽이 **비중 스트레스 테스트**인가;
   - 최종 매수/보유/회피를 여섯 개 차원을 종합해 어떻게 도출했는가. 10년 모델이 r을 감당하지 못한다는 이유로 다른 차원과 thesis 증거를 단독 거부하는 것은 **금지**한다;
   - 매수/보유를 유지하기로 했다면, 10년 스트레스 테스트가 비중 상한을 어떻게 조였는지 설명해야 한다(10년 모델이 없는 척해서는 안 된다).

**버핏식 질문**: 이 r이 2%포인트 틀렸다면 내 결론은 뒤집히는가? 그렇다면 내 결론이 사는 것은 회사인가, 할인율인가? (`flip`의 출력으로 직접 답하며, 말로 얼버무리는 것은 금지한다.)

**돤융핑식 질문**: 주식시장이 내일부터 5년간 문을 닫는다면, 이 가격에 보유하겠는가?

#### 4대 거장 모의 논평(강제 제약: 원문을 먼저 읽고, 인용문 날조 금지)

버핏 / 멍거 / 돤융핑 / 리루의 모의 논평을 쓰기 전에, 거장마다 **반드시** 다음을 수행한다:

1. **원 출처를 Read한다**: 본 저장소 안에서 해당 회사와 관련된 1차 자료(예: `reports/.../돤융핑-쉐추발언-*.md`, 거장의 공개 서한/연설 발췌, 이미 인용된 권위 있는 전재본)를 우선 읽는다. 저장소에 보관본이 없으면 공개적으로 검증 가능한 출처(雪球 원문, 주주서한, 인터뷰 전문)를 쓰고 논평 아래에 URL이나 파일 경로를 표기한다.
2. **원문을 인용한다**: 거장마다 최소 **검증 가능한 원문 1건**(짧은 인용 + 출처)을 제시한다. 모의 논평은 그 원문의 입장을 연장한 것이어야 하며, 반대 입장으로 바꿔서는 안 된다.
3. **인용문 날조 금지**: 거장이 하지 않은 말을 지어내서는 안 되며, 거장의 이름으로 그의 공개 입장과 반대되는 결론을 보증해서도 안 된다.
4. **충돌 처리**: 본 보고서의 "관망/회피"에 맞추려고 쓴 모의 논평의 입장이 이미 Read한 원문과 **반대**라면 반드시 둘 중 하나를 택한다——**(a)** 논평을 고쳐 원문과 일치시키거나, **(b)** 보고서에 「거장의 공개 입장과 충돌: 원문=…; 본 보고서 밸류에이션 스트레스 테스트=…」라고 명시적으로 표기한다. 조용히 왜곡하는 것은 **금지**한다.
5. **읽지 못하면 대변하지 않는다**: 어느 거장이 해당 회사/해당 의제에 대해 Read할 원문이 충분하지 않으면 「자료 부족, 모의 대변하지 않음」이라고 적는다. 학습 말뭉치에 기대어 "그럴듯하게 들리는" 논평을 지어내서는 안 된다.

## 출력 요구사항

1. 모든 분석은 데이터로 뒷받침하고 데이터 출처를 붙인다
2. 핵심 데이터는 Markdown 표로 제시한다
3. 각 모듈 끝에는 해당 거장의 "질문"이 반드시 있어야 한다
4. 최종적으로 전체 보고서를 `~/[회사명]투자연구보고서.md`에 쓴다
5. 결론은 명확해야 하며, 매수/관망/회피 제안을 내놓는 것을 피하지 않는다
6. 밸류에이션 부분은 구체적인 가격 구간을 제시해야 한다
7. **보고서 첫머리**에는 반드시 "정보 풍부도 등급"(A/B/C)과 "AI 연구 한계 고지"를 포함한다
8. **보고서 끝**에서는 반드시 "AI 분석 신뢰도"와 "투자 확실성"을 구분한다——전자는 자료량에, 후자는 사업의 본질에 달려 있다. 본 보고서의 어느 결론이 충분한 데이터에 기반하고 어느 결론이 제한된 정보에 의한 추론인지 독자에게 분명히 알린다
9. 회사가 C급(정보 희소)에 해당하면, 보고서 끝에 반드시 "1차 검증이 필요한 질문 목록"을 나열한다——독자가 현장 조사, 제품 체험, 공급망 인터뷰 등으로 AI의 사각지대를 보완하도록 권한다

## 데이터 표본 검사(통과 절차)

보고서를 파일에 쓴 뒤 **반드시** 데이터 표본 검사를 수행하고, 통과한 뒤에야 발행할 수 있다:

**Step 1 — 표본 검사 목록 추출(15% 무작위 표본):**
```bash
python3 tools/report_audit.py extract \
  --report <보고서 파일 경로>
```
JSON 템플릿이 출력되며, 항목마다 `fetched_value`(채워야 할 값)가 있다.

**Step 2 — 데이터 조회 및 검증:**
목록의 데이터 포인트마다 `skills/financial-data.md` 규범에 따라 신뢰할 수 있는 출처에서 데이터를 가져와
(미국 주식: macrotrends+stockanalysis; 홍콩 주식: aastocks+macrotrends; A주: 东方财富+巨潮资讯),
`fetched_value` / `fetched_source` / `fetched_value2` / `fetched_source2`에 채운다.

**Step 3 — 판정 출력:**
```bash
python3 tools/report_audit.py verdict \
  --results '<채운 JSON>' \
  --report <보고서 파일명>
```

- **【통과】**: 모든 표본 포인트의 편차 ≤ 1% → 보고서 발행 가능
- **【반려】**: 어느 한 포인트라도 편차 > 1% → 해당 데이터를 수정한 뒤 다시 표본 검사하고, 통과할 때까지 반복한다

**Step 4 — 밸류에이션 기준 재검사(10년 할인 밸류에이션이 포함된 보고서는 반드시 수행):**

보고서에 10년 IRR이나 종말가치 배수가 나왔다면, 최종 확정본에 쓴 파라미터로 audit를 한 번 더 돌려 보고서에 적힌 수치가 통과 당시와 일치하는지 확인한다:

```bash
python3 tools/terminal_value.py audit \
  --currency {통화} --r {r} --roic {ROIC} --g {3구간g} --rf {무위험이자율} \
  --beta {β} --discrete-risks "{리스크귀속목록}"
```

- **【통과】**(종료 코드 0) → 보고서 발행 가능
- **【반려】**(종료 코드 1) → 수정 후 다시 실행하고, 통과할 때까지 반복한다

**이 단계를 건너뛸 수 없는 이유**: 7단계의 audit는 수치를 계산하기 전에 한 것이고, 보고서를 쓰는 과정에서는 되돌아가 g나 r을 조정하는 일이 잦다. **통과 직전의 마지막 audit야말로 보고서를 책임지는 audit이다.**
