# 투자연구팀: 4개 역할 병렬 분석 프레임워크

$ARGUMENTS 에 대해 팀 방식의 투자 연구 분석을 수행한다. Team 도구를 사용해 실제 멀티 Agent 병렬 연구팀을 만든다.

## 실행 절차

### 1단계: 팀 프레임워크 제시

사용자에게 아래 팀 구조를 보여주고, 확인을 받은 뒤 시작한다:

| 역할 | 책임 | 분석 프레임워크 |
|------|------|----------|
| **team-lead**(너 자신) | 총괄 조율, 종합 판단, 최종 보고서 산출 | 4대 거장 종합 프레임워크 |
| **business-analyst** | 비즈니스 모델 & 해자 분석 | 돤융핑 관점 |
| **financial-analyst** | 재무제표 & 밸류에이션 분석 | 버핏 관점 |
| **industry-researcher** | 산업 구도 & 경쟁 구도 | 멍거 관점 |
| **risk-assessor** | 리스크 평가 & 경영진 판단 | 리루 관점 |

### 1.5단계: AI 연구 편향 평가

팀을 만들기 전에, 해당 회사의 "AI 연구 가능성" 평가를 사용자에게 먼저 보여준다:

**정보 풍부도 등급**(연구 전략을 결정한다):
| 등급 | 특징 | 연구 전략 조정 |
|------|------|------------|
| A등급(정보 풍부) | 상장한 지 오래됨, 증권사 커버리지 넓음 | 팀의 중점을 **반대 검증**과 **비컨센서스 관점**에 두고, 시장과 똑같은 "옳지만 쓸모없는 말"을 내놓지 않는다 |
| B등급(정보 보통) | 상장한 지 얼마 안 됨, 커버리지 제한적 | 각 Agent의 추산 데이터에는 반드시 신뢰도를 표기하고, team-lead는 종합 시 "데이터 충분도"를 표기한다 |
| C등급(정보 희소) | 비인기/신규 상장/신흥시장 | 팀은 "제1원리 모드"로 전환한다: 보고서의 완결성을 추구하지 않고, 사업 본질에 관한 핵심 질문 몇 개에 집중한다 |

**핵심 주의**: 자료가 많다≠확실성이 높다, 자료가 적다≠확실성이 낮다. AI가 출력할 수 있는 신뢰도 ≠ 투자의 실제 확실성. 확실성은 비즈니스 모델 자체에서 나오지, 자료의 양에서 나오지 않는다.

등급 결과를 각 Agent에게 알려 연구 방식에 반영하게 한다.

### 1단계 ¾: WebSearch 권한 사전 점검(핵심 · Agent의 조용한 성능 저하 방지)

팀을 만들고 백그라운드 Agent를 시작하기 **전에**, 반드시 WebSearch 권한이 허용되어 있는지 먼저 확인한다.

**사전 점검이 필수인 이유**: 이 skill은 `run_in_background: true` 로 백그라운드 하위 Agent 4개를 시작하는데, **백그라운드 Agent는 사용자에게 대화형 권한 확인창을 띄울 수 없다**. `WebSearch` 가 `.claude/settings.local.json` 의 `permissions.allow` 허용 목록에 없으면, 하위 Agent의 웹 검색은 **조용히 차단**되고, 학습 지식(지식 기준일이 있음)만으로 답하는 상태로 떨어지면서도 프레임워크대로 "완전해 보이지만 실제로는 웹을 조회하지 않은" 가짜 연구를 내놓는다. 이것이 이 skill의 가장 위험한 실패 유형이다(issue #58 참조).

**사전 점검 절차**:
1. Bash로 허용 목록에 WebSearch가 있는지 확인한다:
   ```bash
   grep -l '"WebSearch"' .claude/settings.local.json ~/.claude/settings.local.json 2>/dev/null
   ```
2. 두 곳 모두 검색되지 않으면(즉 허용되지 않음) → **멈추고, Agent를 시작하지 않는다**. 사용자에게 다음을 안내한다:
   > ⚠️ WebSearch가 권한 허용 목록에 없는 것으로 확인됐다. 백그라운드 연구 Agent가 웹에 접속할 수 없어, 학습 지식만으로 답하는 상태로 떨어진다. 먼저 `.claude/settings.local.json` 의 `permissions.allow` 에 `"WebSearch"` 를 추가한 뒤(또는 `/permissions` 를 실행해 체크한 뒤) 이 명령을 다시 실행한다.
3. 검색되면 → 정상 진행한다.

### 2단계: 팀 생성

TeamCreate로 팀을 만든다:
- team_name: `{회사명}-research`(영문 소문자, 예: `meituan-research`)
- agent_type: `team-lead`

### 3단계: 작업 4개 생성

TaskCreate로 아래 4개 작업을 만든다(각각 subject, description, activeForm을 갖춰야 한다):

#### 작업 1: 비즈니스 모델 분석
- subject: `{회사명} 비즈니스 모델, 해자, 사용자 가치 분석`
- description 포함 내용:
  1. 비즈니스 모델의 본질: 핵심 사업 정의, 매출 구조 분해
  2. 플랫폼/제품의 플라이휠 효과가 어떻게 돌아가는가
  3. 해자 분석: 브랜드/전환비용/네트워크 효과/규모의 효과/기술 장벽, 하나씩 검증
  4. 사용자/고객 가치: 각 당사자에게 어떤 고유한 가치를 만들어 주는가
  5. 사업 매트릭스와 시너지 효과
  6. 돤융핑의 "좋은 사업" 기준 평가: 차별화, 가격 결정력, 지속 가능한 경쟁우위
  7. 최신 실적(재무보고서), 산업 보고서 등 공개 정보를 검색하도록 요구

#### 작업 2: 재무 및 밸류에이션 분석
- subject: `{회사명} 재무 데이터, 수익성, 밸류에이션 분석`
- description 포함 내용:
  1. 최근 3-5년 매출, 순이익, 영업이익 추세
  2. 수익성 지표: ROE, ROA, 매출총이익률, 영업이익률
  3. 현금흐름 분석: 영업현금흐름, 잉여현금흐름, 자본적 지출
  4. 재무상태표 건전성: 현금 보유, 부채비율, 유동성
  5. 밸류에이션 분석: PE/PS/PB/EV 등, 과거 및 동종업계와 비교
  6. 안전마진 평가: 내재가치 vs 현재 주가
  7. **금융 엄밀성 검증(반드시 Bash로 도구를 호출한다. 암산 금지)**:
     - 시가총액 검산: `python3 tools/financial_rigor.py verify-market-cap --price {가격} --shares {주식수} --reported {보고된시가총액} --currency {통화}`
     - 밸류에이션 검산: `python3 tools/financial_rigor.py verify-valuation --price {가격} --eps {EPS} --bvps {주당순자산}`
     - 핵심 데이터 교차 검증: `python3 tools/financial_rigor.py cross-validate --field {필드} --values '{JSON}' --unit {단위}`
     - 3개 시나리오 밸류에이션: `python3 tools/financial_rigor.py three-scenario --price {가격} --eps {EPS} --shares {주식수_억} --growth {낙관} {중립} {비관} --pe {낙관PE} {중립PE} {비관PE}`
     - 도구 출력 결과를 검증 기록으로 보고서에 그대로 넣는다

#### 작업 3: 산업 및 경쟁 분석
- subject: `{산업} 산업 구도와 {회사명} 경쟁 구도 분석`
- description 포함 내용:
  1. 산업 규모와 성장: 시장 규모, 성장률, 침투율
  2. 경쟁 구도: 주요 경쟁사 시장점유율, 경쟁 전략 비교
  3. 핵심 경쟁자 위협 평가: 주요 경쟁사를 하나씩 분석
  4. 각 세부 분야의 구도
  5. 산업 추세: 기술 변혁, 정책 영향, 신규 진입자
  6. 산업 사슬 분석: 상·중·하류의 가치 배분
  7. 최신 산업 데이터와 경쟁 동향을 검색하도록 요구

#### 작업 4: 리스크 및 경영진 평가
- subject: `{회사명} 투자 리스크와 경영진 자질 평가`
- description 포함 내용:
  1. 경영진 평가: CEO의 능력범위, 정직성, 전략적 안목, 자본 배분 능력, 과거 의사결정의 질
  2. 규제 리스크: 현재 및 잠재적 규제 영향
  3. 경쟁 리스크: 각 경쟁사의 위협 수준 평가
  4. 사업 리스크: 신사업 적자, 확장의 불확실성
  5. 거시 리스크: 경기 사이클, 산업 사이클의 영향
  6. 지배구조: 지분 구조, 특수관계자 거래, 주주환원 정책
  7. 장기 확실성: 10년 뒤 회사는 어떻게 되어 있을까? 무엇이 비즈니스 모델을 뒤엎을 수 있는가?
  8. 최신 규제 동향, 경영진 발언 등을 검색하도록 요구

### 4단계: 병렬 Agent 4개 시작

Task 도구로 Agent 4개를 동시에 시작한다(**반드시 같은 메시지 안에서 병렬 호출한다**):

각 Agent의 설정:
- `subagent_type`: `general-purpose`
- `run_in_background`: `true`
- `team_name`: 해당 팀 이름
- `name`: 해당 역할 이름(business-analyst / financial-analyst / industry-researcher / risk-assessor)

각 Agent의 prompt 템플릿:

```
너는 {회사명} 투자연구팀의 "{역할 한국어명}"으로, {거장명}의 투자 관점에서 {회사명}을 분석하는 일을 맡는다.

작업 #{작업번호}를 완료한다: {작업 subject}

구체적 요구사항:
{작업 description의 내용}

**연구 방법**:
- WebSearch로 최신 공개 정보(실적, 산업 보고서, 뉴스)를 검색한다
- **재무 데이터는 반드시 독립된 두 출처에서 가져온다**. `skills/financial-data.md` 규범에 따라 수행한다(미국 주식: macrotrends+stockanalysis, 홍콩 주식: aastocks+macrotrends, A주: 东方财富+巨潮资讯, 대만 주식: FinMind `tools/twstock_data.py`+Goodinfo). 두 출처의 오차가 1%를 넘으면 반드시 표시한다
- 데이터의 정확성을 확보하고, 핵심 데이터에는 출처를 표기한다
- 분석은 깊이 있게 하고, 겉핥기에 그치지 않는다
- **웹 조회 실패를 위장하지 않는다**: WebSearch가 차단되거나 사용할 수 없으면, 학습 지식을 웹 조회 결과인 것처럼 꾸미는 것을 금지한다. 반드시 보고서 맨 위에 「⚠️ 본 보고서는 웹에 접속하지 못했으며, 학습 지식(기준일 X)에 기반한다. 신뢰도 하향」이라고 눈에 띄게 표기하고, team-lead에게 사실대로 알려 연구 중단 여부를 결정하게 한다

**출력 요구사항**:
- 보고서는 상세하게 쓰고, 핵심 데이터는 Markdown 표로 제시한다
- 각 분석 차원마다 명확한 결론과 평점이 있어야 한다
- 보고서 끝에 해당 차원의 종합 결론을 둔다

**완료 후**:
1. TaskUpdate로 작업 #{작업번호}를 completed로 표시한다
2. SendMessage로 전체 분석 보고서를 team-lead에게 보낸다(type: "message", recipient: "team-lead")
```

### 5단계: 보고서 수신 및 진행 상황 추적

- 사용자에게 진행 상황표를 실시간으로 보여준다(어느 Agent가 완료했고, 어느 Agent가 아직 연구 중인지)
- 보고서를 한 건 받을 때마다 진행 상황을 갱신하고 그 보고서의 핵심 요점(3-5개)을 보여준다
- 보고서 4건이 모두 도착할 때까지 기다린다

### 6단계: 팀원 종료

보고서를 모두 받은 뒤, Agent 4개에게 shutdown_request를 보낸다(SendMessage 사용, type: "shutdown_request").

### 7단계: 최종 보고서 종합

분석 보고서 4건을 종합해, 아래 구조의 최종 보고서를 산출한다:

---

#### 1. 한 문장 결론
> 투자할 가치가 있는지와 핵심 논리를 한 단락(50-100자)으로 요약한다

#### 2. 4차원 평점 총괄표
| 차원 | 프레임워크 | 평점(별 1-5개) | 핵심 판단 |
|------|------|------------|----------|

종합 평점: X / 5

#### 3. 핵심 데이터 한눈에 보기
핵심 재무 및 경영 지표 표(최근 2년 비교)

#### 4. 차원별 분석 요약
각 차원에서 가장 중요한 발견 3-5개를 뽑는다

#### 5. 투자 논점(Bull vs Bear)
- 🟢 강세 논리(5-7개)
- 🔴 약세 논리(5-7개)

#### 6. 버핏의 매수 전 Checklist
| # | 점검 항목 | 통과? | 설명 |
핵심 점검 항목 10개를 하나씩 평가한다

#### 7. 최종 투자 의견
- 정성 판단표(사업의 질/경영진/밸류에이션/타이밍)
- 유형별 실행 의견표(공격형/안정형/보수형 → 의견+가격 구간)
- 핵심 촉매(비중 확대 신호/비중 축소 신호 각 3-5개)

#### 8. 총평 단락
100-200자의 최종 총평

---

### 8단계: 보고서 저장

완성된 최종 보고서를 `~/{회사명}투자연구보고서_{날짜}.md` 에 쓴다(날짜 형식 YYYYMMDD).

### 9단계: 데이터 표본 점검(출고 승인 절차)

```bash
# Step 1 — 표본 점검 목록 추출(15% 무작위 표본)
python3 tools/report_audit.py extract \
  --report <보고서 파일 경로>

# Step 2 — 목록의 각 항목을 신뢰할 수 있는 출처에서 조회(skills/financial-data.md 참조)

# Step 3 — 통과/반려 판정 출력
python3 tools/report_audit.py verdict \
  --results '<채워 넣은 JSON>' \
  --report <보고서 파일명>
```

**【통과】** 전부 통과 → 보고서 발행 가능. **【반려】** 불통과 항목 있음 → 수정 후 재심사.

### 10단계: 팀 정리

TeamDelete로 팀 리소스를 정리한다.

## 중요 주의사항

1. **Agent 4개는 반드시 병렬로 시작한다**——같은 메시지 안에서 Task 도구를 4번 호출한다
2. **Agent는 SendMessage로 보고한다**——파일 협업이 아니라 메시지 통신이다
3. **데이터 정확성**——Agent가 WebSearch로 최신 데이터를 검색하고, 핵심 데이터를 교차 검증하도록 요구한다
4. **결론은 명확하게**——매수/관망/회피 의견과 구체적 가격 구간을 내놓기를 피하지 않는다
5. **모든 분석은 데이터로 뒷받침한다**——데이터 출처를 첨부한다
6. **인내심 있게 기다린다**——Agent 4개의 연구에는 몇 분이 걸린다. 사용자에게 진행 상황을 실시간으로 갱신한다
