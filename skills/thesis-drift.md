# 투자 논거 표류 탐지: 사실의 변화와 표현의 변화를 구분한다

$ARGUMENTS 에 대해 투자 논거(thesis) 표류 탐지를 수행한다.

**지원 입력 형식**:
- `회사명 이전보고서경로 새보고서경로` — 두 연구 보고서 또는 논거 스냅샷을 지정해 비교한다
- `회사명 reports/{회사명}-thesis-이전날짜.md reports/{회사명}-thesis-새날짜.md` — 날짜가 붙은 두 논거 스냅샷을 비교한다
- `회사명` — `reports/{회사명}-thesis.md` 와 같은 디렉터리의 과거 스냅샷을 자동으로 찾는다. 기준선이 없으면 기준선 부재 처리로 넘어간다

> "사실이 바뀌면 나는 생각을 바꾼다. 당신은 어떤가?" —— 케인스
>
> "주가 변동은 논거 표류가 아니다. 사실이 바뀌어야 표류다." —— AI Berkshire

## 설계 이념

장기 보유에서 가장 어려운 것은 매일 뉴스를 읽는 일이 아니라 다음 세 가지를 구분하는 일이다:
- **사실의 변화**: 매출, 이익률, 경쟁 구도, 경영진 행동, 자본 배분에 검증 가능한 변화가 생겼다
- **가격의 변화**: 시장 심리나 밸류에이션 배수가 변했지만 사업 자체는 변하지 않았다
- **표현의 변화**: 두 보고서의 서술은 다르지만 밑바탕의 증거와 판단은 변하지 않았다

투자 논거 표류 탐지의 목표는 **증거가 변했을 때만 논거의 변화를 인정하는 것**이다. 보고서의 서술 방식이 바뀌었다고 표류를 만들어 내서도 안 되고, 주가가 오르내렸다고 펀더멘털을 오판해서도 안 된다.

이 Skill은 `/thesis-tracker` 가 출력하는 구조화된 차원에 의존한다: 핵심 가정 목록, 레드라인 목록, 밸류에이션 앵커, 추적 기록표. 이 구조가 없으면 먼저 기준선을 보완한 뒤 표류 탐지를 한다.

## 실행 절차

### 1단계: 작동 모드 판단

`$ARGUMENTS` 를 해석한다:
- 보고서 경로 두 개가 주어지면 → **지정 보고서 비교** 모드로 들어간다
- 회사명만 주어지면 → `reports/{회사명}-thesis.md` 와 과거 스냅샷을 찾아 **자동 스냅샷 비교** 모드로 들어간다
- 보고서를 하나만 찾았거나 과거 기준선이 없으면 → **기준선 부재 처리** 모드로 들어간다
- 두 보고서가 같은 회사가 아니면 → 멈추고 사용자에게 확인을 요청한다. 회사 간 표류 판단은 하지 않는다

## 모드 A: 지정 보고서 비교

### A1: 두 보고서를 읽고 검증한다

이전 보고서와 새 보고서를 읽고 다음을 추출한다:
- 보고서 날짜, 회사명, 종목 코드
- 핵심 논거(5문장)
- 핵심 가정 목록
- 레드라인 목록
- 밸류에이션 앵커
- 추적 기록표
- 경영진 자질 판단
- 경쟁 해자 판단
- 현재 권고 행동(매수 / 보유 / 관찰 / 비중 축소 / 전량 매도)

보고서에 핵심 구조가 빠져 있으면 먼저 "구조 누락"으로 표기하되, 본문에서 최대한 증거를 추출한다. 추출할 수 없는 차원은 "판단 불가"로 표기하고 결론을 지어내지 않는다.

### A2: 증거 정규화

두 보고서의 사실 증거를 하나의 표로 정리한다:

| 차원 | 이전 보고서 증거 | 새 보고서 증거 | 데이터 출처 | 검증 가능 여부 |
|------|-----------|-----------|---------|-----------|
| 밸류에이션 앵커 | | | | |
| 핵심 가정 | | | | |
| 레드라인 | | | | |
| 경영진 자질 | | | | |
| 경쟁 해자 | | | | |

**증거만 비교하고 문체는 비교하지 않는다.** 새 보고서와 이전 보고서가 동의어로 바꿔 쓰였거나, 순서가 바뀌었거나, 어조가 달라졌을 뿐 사실 데이터와 판단 임계값이 변하지 않았다면 Unchanged로 판정한다.

### A3: 수치와 밸류에이션 검증

모든 수치 변화는 반드시 `tools/financial_rigor.py` 로 정밀 계산한다. LLM 암산은 금지한다:

```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {현재가격} \
  --eps {EPS} \
  --bvps {주당순자산} \
  --fcf-per-share {주당잉여현금흐름}
```

시가총액, 백분율 변화, 목표가 차이, 시나리오 밸류에이션을 계산해야 하면 다음을 사용한다:

```bash
python3 tools/financial_rigor.py verify-market-cap --price {가격} --shares {주식수} --reported {보고서시가총액} --currency {통화}
python3 tools/financial_rigor.py cross-validate --field {필드} --values '{JSON}' --unit {단위}
python3 tools/financial_rigor.py three-scenario --price {가격} --eps {EPS} --shares {주식수(억)} --growth {낙관} {중립} {비관} --pe {낙관PE} {중립PE} {비관PE}
python3 tools/financial_rigor.py calc --expr '{정밀산식}'
```

핵심 재무 데이터는 독립된 출처 최소 두 곳으로 교차 검증한다. 출처가 부족하거나, 기준이 일치하지 않거나, 재확인할 수 없는 숫자는 반드시 "저신뢰도 / 확인 필요"로 표기한다.

### A4: 차원별 표류 판정

아래 차원을 고정으로 사용하고 임의로 늘리거나 줄이지 않는다:

| 차원 | 판정 중점 | Improved | Unchanged | Weakened |
|------|---------|----------|-----------|----------|
| 밸류에이션 앵커 | 내재가치, PE/PB/FCF Yield, 안전마진, 목표가 구간 | 안전마진이 확대됐거나 내재가치가 상향됐고 도구로 검산됨 | 밸류에이션 구간과 안전마진에 실질적 변화 없음 | 안전마진 축소, 내재가치 하향 또는 밸류에이션 가정 무효화 |
| 핵심 가정 목록 | 매출 증가율, 이익률, 현금흐름, 사용자/주문/생산능력 등 검증 가능한 가정 | 더 많은 가정이 새 증거로 강화됨 | 가정 상태와 증거가 대체로 일치 | 가정이 한계적으로 약화, 손상 또는 붕괴 |
| 레드라인 목록 | 정직성, 규제, 사업 쇠퇴, 경쟁사의 돌파, 경영진의 이상 행동 | 기존 레드라인 리스크가 해소되거나 뚜렷이 하락 | 발동되지 않았고 리스크 수준 불변 | 레드라인이 발동됐거나 발동 확률 상승 |
| 경영진 자질 | 정직성, 자본 배분, 자사주 매입·배당, 실행력, 주주 친화도 | 새 행동이 신뢰도를 높임 | 행동이 기존 판단을 이어감 | 행동이 신뢰를 훼손하거나 자본 배분이 악화 |
| 경쟁 해자 | 시장 점유율, 가격 결정력, 네트워크 효과, 원가 우위, 대체 위협 | 해자가 넓어지거나 경쟁 우위가 검증됨 | 구도에 실질적 변화 없음 | 해자가 약화되거나 경쟁사가 돌파 |

각 차원에는 세 가지 결론만 내릴 수 있다: **Improved / Unchanged / Weakened**.

### A5: 증거 기반 규칙

Unchanged가 아닌 결론은 모두 변화를 일으킨 구체적인 새 증거를 인용해야 한다:
- 재무제표 항목: 예) 매출 증가율, 매출총이익률, 영업현금흐름, 자사주 매입 금액, 순현금
- 규제 공시: 예) 10-K/20-F, 연간보고서, 반기보고서, 홍콩거래소 공시, SEC filing
- 뉴스 사건: 예) 경영진 변동, 규제 처벌, 주요 고객 이탈, 경쟁 제품의 돌파
- 가격과 밸류에이션: 이것이 "밸류에이션 변화"인지 "펀더멘털 변화"인지 반드시 밝히고 혼동하지 않는다

변화를 설명할 증거를 찾지 못하면 반드시 **Unchanged** 또는 **판단 불가**로 판정한다. 표현의 차이로 표류를 추론해서는 안 된다.

### A6: 표류 보고서 출력

#### 보고서 구조

```
1. 비교 대상과 시간 범위
2. 종합 결론: 논거가 표류했는가
3. 차원별 표류표
4. 증거 차이 명세
5. 밸류에이션과 수치 검산
6. 권고 행동의 이동
7. 불확실 항목과 보완이 필요한 출처
8. 다음 추적 중점
```

#### 차원별 표류표

| 차원 | 이전 판단 | 새 판단 | 표류 방향 | 촉발 증거 | 신뢰도 |
|------|-------|-------|:--------:|---------|:------:|
| 밸류에이션 앵커 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 핵심 가정 목록 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 레드라인 목록 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 경영진 자질 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |
| 경쟁 해자 | | | Improved / Unchanged / Weakened | | 높음/중간/낮음 |

**Unchanged 행의 촉발 증거에는 `—` 를 쓴다. 표를 채우려고 증거를 지어내지 않는다.**

#### 종합 결론이 반드시 답해야 할 것

1. **논거가 표류했는가?** 표류 없음 / 긍정적 표류 / 부정적 표류 / 증거 부족으로 판단 불가
2. **표류는 어디에서 왔는가?** 밸류에이션 / 펀더멘털 / 경영진 / 경쟁 구도 / 레드라인 사건
3. **사실의 변화인가, 가격의 변화인가?** 명확히 나누어 설명한다
4. **권고 행동은 어떻게 이동하는가?** 예: Watch → Buy, Buy → Hold, Hold → Reduce, Reduce → Exit
5. **다음에는 어떤 증거가 필요한가?** 다음 실적 / 규제 공시 / 경영진 설명 / 경쟁사 데이터

## 모드 B: 자동 스냅샷 비교

### B1: 스냅샷 찾기

`reports/` 에서 다음을 찾는다:
- `reports/{회사명}-thesis.md`
- `reports/{회사명}-thesis-*.md`
- `reports/{회사명}/` 디렉터리에서 `thesis`、`论文`、`追踪`、`논거`、`추적` 을 포함하는 보고서

시점이 가장 이르고 구조가 온전한 파일을 이전 보고서로, 시점이 가장 최근인 파일을 새 보고서로 고른다. 사용자가 날짜를 지정하면 사용자 지정을 따른다.

### B2: 잘못된 짝짓기 방지

비교 전에 반드시 확인한다:
- 회사명 또는 종목 코드가 일치한다
- 보고서 날짜가 서로 다르다
- 두 보고서 모두 추출 가능한 논거 구조나 연구 결론을 담고 있다

같은 회사임을 확인할 수 없으면 멈추고 사용자에게 명확한 경로를 요청한다.

### B3: 모드 A 수행

유효한 스냅샷 두 개를 찾으면 모드 A대로 끝까지 수행한다.

## 모드 C: 기준선 부재 처리

보고서를 하나만 찾았거나 이전 스냅샷을 찾지 못한 경우:

1. 명확히 밝힌다: **비교할 과거 기준선이 없어 표류 탐지를 수행할 수 없다**
2. 기억이나 시장 인상에 기대어 이전 논거를 지어내지 않는다
3. 사용자가 먼저 `/thesis-tracker {회사명} 논거 수립` 으로 구조화된 기준선을 만들도록 안내한다
4. 현재 보고서가 이미 충분히 온전하다면, 이를 `reports/{회사명}-thesis.md` 로 저장해 향후 표류 탐지의 기준선으로 삼도록 권할 수 있다

출력 형식:

```
논거 표류 탐지를 수행할 수 없음: 과거 기준선 없음.

찾은 것:
- 현재 보고서: {경로 / 찾지 못함}
- 과거 기준선: 찾지 못함

권고:
1. 먼저 /thesis-tracker {회사명} 논거 수립 을 실행한다
2. 다음에 새 실적이나 중대 사건이 나온 뒤 /thesis-drift {회사명} 이전보고서 새보고서 를 실행한다
```

## 핵심 원칙

- **증거가 표현에 우선한다** — 동의어로 바꿔 쓴 것은 표류가 아니다. 사실 증거가 변해야 표류다
- **펀더멘털이 주가에 우선한다** — 주가 등락은 밸류에이션 앵커에만 영향을 주며, 사업의 질을 자동으로 바꾸지 않는다
- **수치는 반드시 검산한다** — 모든 백분율, 밸류에이션 배수, 목표가 차이는 `tools/financial_rigor.py` 를 사용한다
- **불확실하면 불확실하다고 표기한다** — 출처가 없거나, 기준이 일치하지 않거나, 재확인할 수 없으면 억지로 판정하지 않는다
- **레드라인은 따로 처리한다** — 레드라인 발동은 싼 밸류에이션보다 우선순위가 높으며, 낮은 PE에 가려져서는 안 된다
- **출력은 복기할 수 있어야 한다** — 모든 Improved / Weakened 결론은 구체적 증거까지 거슬러 올라갈 수 있어야 한다
