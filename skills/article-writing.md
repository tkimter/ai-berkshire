# 게시글 작성: 작가-편집자-독자 3 Agent 협업

$ARGUMENTS 에 대해 심층 연구를 수행해, 바로 발행할 수 있는 게시글 한 편을 산출한다. 세 Agent가 각자 역할을 맡는다: 작가는 깊이 있는 초고를 쓰고, 편집자는 구조와 표현을 다듬고, 독자는 목표 독자의 관점에서 읽고 검토한다.

**지원 입력 형식**: 주제 설명. 예: `대형 모델 OPD 기술 해설`, `Qwen3 기술 보고서 해설`, `버핏은 왜 기술주를 사지 않는가`

---

## 설계 철학

좋은 게시글은 세 가지 차원을 동시에 충족해야 한다:
1. **깊이**——시간을 들여 끝까지 읽은 사람에게 부끄럽지 않아야 한다(작가 담당)
2. **가독성**——구조가 명확하고, 리듬이 좋고, 독자를 쫓아내지 않는다(편집자 담당)
3. **정말로 이해된다**——목표 독자가 중간에 포기하지 않는다(독자 담당)

혼자 쓰면 "자기만족"에 빠지기 쉽다——쓴 사람은 명확하다고 느끼지만, 읽는 사람은 이해하지 못한다. 3 Agent 협업의 본질은 **외부 관점을 강제로 끌어들이는 것**이다.

---

## 1부: 연구와 소재 수집

### 1단계: 글의 포지셔닝 확정

쓰기 전에 먼저 다음 정보를 확인한다(사용자가 지정하지 않았으면 먼저 묻는다):

| 차원 | 확인할 사항 | 기본값 |
|------|---------|--------|
| **목표 독자** | 기술 배경 수준 | 기술 배경이 조금 있지만 해당 분야 전문가는 아님 |
| **글의 깊이** | 대중 교양/중간 깊이/하드코어 | 중간 깊이(수식이 있되 명확히 설명한다) |
| **글의 길이** | 글자 수 범위 | 3000-4000자 |
| **원본 논문/자료 다운로드 필요 여부** | PDF/삽화 필요 | 예 |
| **문체** | 격식체/대화체/날카로운 문체 | 대화체(똑똑한 친구에게 쓰듯이) |

### 2단계: 심층 연구

Agent 도구로 연구 Agent 2-3개를 **병렬**로 시작해, 충분한 소재를 수집한다:

**연구 Agent A: 핵심 내용 연구**
- 논문 해설인 경우: 논문 PDF 다운로드, 핵심 기여·핵심 도표·실험 결과 추출
- 기술 주제인 경우: 최신 진전, 핵심 논문, 기술 세부사항 검색
- 비즈니스/투자 주제인 경우: 최신 데이터, 산업 보고서, 경쟁 구도 검색

**연구 Agent B: 산업 배경과 응용**
- 해당 기술/주제의 산업 현장 적용 상황을 검색한다
- 어떤 회사가 쓰고 있는가? 효과는 어떤가?
- 최신 발전 추세와 이정표가 된 사건

**연구 Agent C(선택): 경쟁 제품/비교 연구**
- 같은 부류의 방법/제품 비교
- 역사적 발전 흐름
- 향후 진화 방향

### 3단계: 소재 틀 정리

연구 Agent가 모두 끝나면 다음을 정리한다:
1. **핵심 논점**(글이 전하려는 핵심 메시지를 한 문장으로 요약)
2. **핵심 데이터**(가장 충격이 큰 데이터 포인트 3-5개)
3. **삽화 목록**(어떤 그림이 필요하고, 출처는 무엇인가)
4. **글의 개요**(6-8개 장의 제목과 핵심 내용)

## 2부: 작가 Agent의 초고 작성

Agent 도구로 **작가 Agent**를 시작하고, 상세한 집필 지시를 준다.

### 작가 Agent의 Prompt 템플릿

```
너는 심층 기술 글을 쓰는 작가(Author Agent)로, 게시글 한 편을 써야 한다.

## 목표 독자
{1단계에서 확정한 독자 프로필}

## 문체 요구사항
- 순수 한국어로 표현하고, 한국어와 영어를 뒤섞지 않는다(기술 용어는 처음 나올 때 영어를 병기하고, 이후에는 한국어로 쓴다)
- 똑똑한 친구에게 써 주는 기술 교양 글처럼 쓴다. 학술 논문 번역이 아니다
- 비유로 이해를 돕되, 비유는 꼭 들어맞고 진부하지 않아야 한다
- 핵심 수식/데이터는 넣되, 하나하나 쉬운 말로 설명한다
- emoji를 쓰지 않는다
- 단락은 4줄을 넘지 않는다(모바일 읽기 환경)

## 핵심 내용
{정리한 소재, 데이터, 논점}

## 글 구조 요구사항
1. **도입부(첫 3단락)**: 반드시 강한 훅이 있어야 한다——데이터의 충격이나 직관에 반하는 결론으로 시작하고, 온건한 비유로 시작하지 않는다
2. **배경**: 이 일이 왜 중요한가? 어떤 문제를 푸는가?
3. **핵심 내용(2-3절)**: 기술적 깊이는 여기서 드러낸다. 다만 기술 포인트마다 "쉬운 말 번역"이 있어야 한다
4. **실증/사례**: 데이터와 사례로 말하고, 공허한 이야기를 하지 않는다
5. **산업 영향/전망**: 이 일이 산업에 무엇을 뜻하는가
6. **맺음말**: 전파력 있는 판단 한 문장으로 마무리한다. 캡처해서 공유하기 좋아야 한다

## 삽화 요구사항
- 논문 해설류 글: 반드시 논문 PDF에서 원본 그림을 추출해, `![설명](상대경로)` 로 글에 직접 삽입한다. [그림X: 설명] 같은 자리표시자를 쓰지 않는다
- 추출 방법: pdftoppm으로 PDF 페이지를 고해상도 PNG로 렌더링하고(최소 900 DPI), PIL로 대상 도표 영역을 잘라낸다
- 그림 한 장은 500KB 이상으로 해 고화질을 확보한다
- 그림은 모두 `assets/{주제약칭}/` 디렉터리에 저장한다
- 논문이 아닌 글: 삽화가 필요하면 적절한 그림을 검색해 내려받고, 마찬가지로 직접 삽입한다

## 수식 요구사항
- 모든 수학 수식은 LaTeX 형식을 쓴다: 행 내 수식은 `$...$`, 독립 수식은 `$$...$$`
- 일반 텍스트로 수식을 쓰는 것을 금지한다(예: `> D_KL(P || Q) = ...`). 반드시 LaTeX 렌더링 형식을 쓴다
- 수식마다 뒤에 여전히 "쉬운 말 번역"을 붙인다

완전한 글 초고를 약 {목표 글자 수}자로 쓴다.
```

### 작가 Agent 완료 후

초고 파일이 생성됐는지 확인하고, 전문을 읽어 내용의 완결성을 확인한다.

## 3부: 편집자 Agent + 독자 Agent 병렬 검토

초고가 완성되면, Agent 도구로 **같은 메시지** 안에서 편집자 Agent와 독자 Agent를 시작한다.

### 편집자 Agent의 Prompt 템플릿

```
너는 경력 많은 편집자(Editor Agent)다. 아래 글을 다듬고 검토한다.

## 검토 기준
1. **제목**: SNS 피드에서 클릭을 끌 수 있는가? 잘리지 않는가(30자 초과)?
2. **도입부**: 첫 3단락이 독자를 붙잡을 수 있는가? 훅이 충분히 강한가?
3. **구조**: 논리의 사슬이 매끄러운가? 비약이나 단절은 없는가?
4. **깊이와 가독성의 균형**: 수식/기술 부분이 정말로 쉬운가? "쉬운 척하지만 제대로 설명하지 않은" 곳은 없는가?
5. **리듬**: 너무 긴 단락은 없는가? 각 절의 길이가 적절한가?
6. **삽화**: 그림이 실제로 삽입됐는가(자리표시자가 아닌가)? 독자가 시각적 도움을 가장 필요로 하는 지점에 나오는가?
7. **맺음말**: 전파력이 있는가? 독자가 다 읽고 공유하고 싶어 하겠는가?

## 글 전문
{완전한 초고}

## 출력 형식
1. 총평(3-5문장)
2. 제목 수정 제안(대안 2-3개 제시)
3. 절별 수정 제안("원문→수정 제안"의 구체적 대조를 제시)
4. 가장 핵심적인 개선점 3개
```

### 독자 Agent의 Prompt 템플릿

```
너는 {목표 독자 프로필}(Reader Agent)이다. 독자의 관점에서 아래 글을 읽고 검토한다.

## 너의 배경
{목표 독자의 지식 수준과 읽기 습관을 구체적으로 서술}

## 글 전문
{완전한 초고}

## 다음 질문에 답한다
1. 첫 3단락을 읽고 나서, 계속 읽겠는가? 왜 그런가?
2. 어느 부분이 "이해되지 않거나" "다시 읽어야 이해되는가"? 구체적으로 어느 문장인가?
3. 기술/수식 부분을 이해했는가? "쉬운 말 번역"이 도움이 됐는가?
4. 글의 핵심 비유가 들어맞는가? 더 나은 비유가 있는가?
5. 너무 긴가, 너무 짧은가? 어디에서 인내심을 잃겠는가?
6. 다 읽은 뒤 글의 핵심 관점을 한 문장으로 요약할 수 있는가?
7. 이 글을 공유하겠는가? 공유할 때 뭐라고 말하겠는가?
8. 알고 싶은데 글이 다루지 않은 질문이 있는가?
```

## 4부: 최종 원고 확정

### 1단계: 두 Agent의 피드백 종합

다음과 같은 고빈도 문제에 중점을 둔다:

| 문제 유형 | 편집자의 흔한 피드백 | 독자의 흔한 피드백 | 처리 방식 |
|---------|------------|------------|---------|
| 도입부가 약함 | 훅이 충분히 강하지 않다 | 첫 3단락에서 계속 읽을 동기가 없다 | 데이터/직관에 반하는 결론으로 도입부를 다시 쓴다 |
| 기술 단락이 독자를 쫓아냄 | 수식이 너무 빽빽하다 | 어떤 단락은 3번 다시 읽어야 한다 | 수식을 지우거나 그림으로 바꾸고, 더 직관적인 비유를 넣는다 |
| 리듬이 늘어짐 | 어떤 절이 너무 길다 | 어느 지점에서 인내심을 잃는다 | 합치거나 줄인다(특히 후반부에 반복되는 기술 설명) |
| 맺음말이 힘없음 | 전파력이 부족하다 | 공유하지 않겠다 | 캡처해서 퍼뜨릴 수 있는 판단 한 문장으로 다시 쓴다 |
| 개념의 비약 | 논리에 단절이 있다 | 어느 지점에서 "갑자기 이해가 안 된다" | 연결 문장이나 배경 설명을 보충한다 |

### 2단계: 수정 실행

피드백에 따라 글을 다시 쓴다. 핵심 수정 원칙:

1. **편집자와 독자가 모두 지적한 문제는 반드시 고친다**
2. **편집자만 지적한 문제는 대체로 고친다**(편집자의 전문적 판단은 보통 정확하다)
3. **독자만 지적한 문제는 상황을 보고 고친다**(독자 피드백은 실제 경험을 대표하지만, 모든 항목에 대응할 필요는 없다)
4. **둘이 충돌하면 독자 쪽으로 기운다**(편집자는 완벽을 추구하지만, 독자의 경험이 최종 기준이다)

### 3단계: 삽화 추출

논문 해설류 글은 최종 원고 확정 전에 반드시 삽화 추출을 마친다:

1. **렌더링**: `pdftoppm -png -r 900 -f {페이지번호} -l {페이지번호} 논문.pdf /tmp/page`(900 DPI부터 시작하고, 그림이 500KB에 못 미치면 1200 또는 1500 DPI로 올린다)
2. **위치 확인**: 먼저 150 DPI로 전체 페이지를 렌더링하고, 각 도표의 픽셀 좌표를 눈으로 확인한다
3. **잘라내기**: PIL로 좌표에 따라 잘라내고, `compress_level=1` 로 저장해 한 장당 ≥ 500KB를 확보한다
4. **저장**: `assets/{주제약칭}/` 디렉터리에 저장하고, 이름은 `fig{번호}-{설명}.png` 로 짓는다
5. **삽입**: 글에서 `![설명](../../assets/{주제약칭}/fig{번호}-{설명}.png)` 로 참조한다

### 4단계: 최종 파일 산출

최종 원고를 md 파일로 저장하고, 파일 끝에 논문/자료 원문 링크를 붙인다:

```markdown
**논문 원문:**
- arXiv: {링크}
```

## 글쓰기 금지선

1. **데이터를 지어내지 않는다**. 인용하는 데이터에는 반드시 출처가 있어야 하고, 찾지 못하면 "추정"이라고 표기한다
2. **AI 말투를 쓰지 않는다**. "함께 살펴보자", "주목할 만한 점은", "말하지 않을 수 없다" 같은 상투어를 금지한다
3. **과장된 약속을 하지 않는다**. 기술 글에서 "파괴적인", "혁명적인"이라고 말하지 않고, 데이터로 말한다
4. **수식에는 반드시 쉬운 말을 붙인다**. 수식마다 뒤에 "사람 말로 옮기면……" 단락이 있어야 한다
5. **수식은 반드시 LaTeX로 쓴다**. `$$...$$` 형식을 쓰고, 일반 텍스트 수식을 금지한다
6. **삽화는 반드시 실제로 삽입한다**. 논문 해설류는 PDF에서 고화질 원본 그림(≥500KB)을 추출하고, `[그림X]` 자리표시자를 금지한다
7. **표의 괄호 주석은 정밀해야 한다**. 개념을 서술할 때 정확한 정의를 쓰고, 모호한 술목 구문을 쓰지 않는다(예: "교사의 텍스트를 배운다"가 아니라 "텍스트가 교사에게서 나온다")
8. **비유는 처음부터 끝까지 일관되게 쓴다**. 글 전체에 주된 비유 하나를 쓰고, 절마다 새 비유로 바꾸지 않는다
9. **맺음말에는 반드시 전파력이 있어야 한다**. 마지막 문장은 따로 캡처해 공유할 만해야 한다
